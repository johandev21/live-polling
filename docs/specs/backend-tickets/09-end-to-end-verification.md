## Parent

[#1 Build backend MVP for live polling platform](https://github.com/johandev21/live-polling/issues/1)

## What to build

Verify the complete backend contract as a frontend-ready system through Vitest HTTP and Socket.io integration tests, concurrency tests, failure tests, and coverage reporting.

## Acceptance criteria

- [ ] A verified host can authenticate, create a session, author polls, start it, and control its lifecycle.
- [ ] A participant can join from a room code, receive the active poll, submit a response, and receive permitted results.
- [ ] Host and participant authorization boundaries are covered end to end.
- [ ] Single-choice, multiple-choice, and open-ended flows are covered end to end.
- [ ] Response replacement, idempotent retry, and close-race behavior are covered.
- [ ] Realtime updates, revisions, reconnect snapshots, and presence are covered.
- [ ] A failed realtime publication cannot lose an accepted response.
- [ ] Concurrent poll-open and response-submit scenarios assert final authoritative state.
- [ ] Tests run against PostgreSQL and Redis test services rather than replacing durable behavior with mocks.
- [ ] External mail delivery remains mocked behind the mailer boundary.
- [ ] Vitest coverage is generated by a repeatable command suitable for CI.
- [ ] The backend contract is documented sufficiently for the existing frontend to integrate without inventing domain behavior.
